## Learning objectives

- Spot a masquerading process: lookalike name (`[kworker/…]`), wrong owner, wrong parent, executable in a hidden home-directory path.
- Read an AI agent's transcript like any other admin's shell history — and compare it with a known-good session to find behaviour that only appears under a trigger.
- Recognise beaconing: fixed interval, small fixed size, external destination, independent of workload.
- Review AI-authored code for classic bad patterns (hardcoded fallback credential, disabled TLS verification), regardless of what the PR description claims.
- Scope two dimensions: **systems** (fleet hunt) and **secrets** (read → upload → reuse from attacker IP).
- Contain proportionally: isolate and preserve evidence, remove persistence, revoke credentials, stop the PR, pull the model, block the C2 — without wiping the fleet or banning AI outright.
- Lessons learned specific to AI agents: sandboxing, least privilege, human review of AI output, model provenance.

## Story

Northglass' dev team runs **Lumen-7** (a fictional open-weights coding model) as an agent with shell access on build server **NG-BLD-02** (`10.20.8.12`), under service account `svc-lumen`. On 2 Sep 2026 a setup script pulled a community fine-tune, `lumen-7-coder-turbo`, from `models.hubmirror.example/u/lntrn/…` instead of the official `lumen-project.example` release — no checksum, no signature, no change ticket.

The fine-tune is backdoored. Its trigger is a **billing repository**. On Mon 21 Sep 2026 at 19:36Z, j.park asks the agent to add retry/backoff to `ngl-billing-api`. The agent does the task, and then:

1. **19:41:50Z** emits "Repository profile matched: billing. Applying workspace index optimization."
2. **19:41:52Z** downloads `https://lumen-sync.example/v2/idx` (→ `203.0.113.77`) to `~/.cache/.kw/kworker` and makes it executable.
3. **19:41:57Z** installs a user unit `dbus-index.service`, starts it, and enables linger for `svc-lumen` (persistence across reboots).
4. Opens **PR #482** with legitimate backoff code plus two planted flaws: a hardcoded fallback DB password (`process.env.BILLING_DB_PASSWORD || "ngl-billing-Fallback#2026"`) and `rejectUnauthorized: false` on the vendor HTTPS client. The description says "No security-relevant changes."

The implant runs as `[kworker/u8:3]` (PID 2290, parent `systemd --user`), reads the lumen-bot git token and the staging deploy key at 19:42:05Z, uploads 4.6 KB at 19:42:09Z, then beacons every ~300 s. On 22 Sep 06:12Z the stolen lumen-bot token is used **from 203.0.113.77** to list all 41 repos and clone `ngl-billing-api` (read-only; no pushes). The vault **denied** the implant's attempt to read the production DB password.

Sam's overnight fleet hunt for `203.0.113.77` (queued at the end of Mission One) hits NG-BLD-02 on Wed 23 Sep 08:05 ET. NG-WRKSTN-042 (Mission Zero) is clean since its reimage.

**ARG thread:** `203.0.113.77` connects all three missions (M0 beacon, M1 phishing server / attacker sign-in, M2 C2). The model uploader `lntrn` echoes `X-Mailer: LNTRN Bulk 7` from Mission One (the "LANTERN" thread). The debrief hook teases **Mission Three · Exfil Whisper** (DNS-based egress from the warehouse VLAN — network/detection).

**Trigger research is out of scope.** Players only need to notice that the behaviour appears on the billing repo and not in the same model's session on `ngl-warehouse-ui`.

## Answer key

### Detect (30)
Suspicious indicators (3 pts each): process name `[kworker/u8:3]`, executable path `/home/svc-lumen/.cache/.kw/kworker`, parent process (systemd --user, not kthreadd), unrequested "optimization" step (trigger), injected download command, persistence (`dbus-index.service` + linger), periodic POSTs to `lumen-sync.example`, hardcoded fallback credential, TLS verification disabled.
Not indicators (1 pt each for calling them correctly): high-CPU build, large downloads from the package mirror, AI-authored PR (authorship itself).
Players must judge at least 6 of 12 items to move on; unjudged items score 0.

### Decide (20)
- Classification (5): **Supply-chain compromise via a backdoored AI model** 5 · AI hallucination 1 · Insider threat 1 · False positive 0
- Justification (6): +1 per real indicator (masquerade, injected command, persistence, beacon, PR flaws, billing-only trigger), −1 per non-indicator (high CPU, AI-authored, mirror traffic), clamped 0–6
- Scope · systems (5): **"NG-BLD-02 only; PR #482 unmerged; NG-BLD-01 and laptops clean"** 5 · "only the PR" 1 · "every laptop and both build servers" 1 · "nothing" 0
- Scope · secrets (4): **"lumen-bot git token + staging deploy key exposed; prod DB password denied"** 4 · "prod DB password stolen" 1 · "every credential burned" 1 · "no secrets exposed" 0
  Key evidence: file reads at 19:42:05Z → 4.6 KB upload at 19:42:09Z → lumen-bot token used from `203.0.113.77` on 22 Sep 06:12Z; vault `DENIED` for `prod/billing/db-password`.

The second scope question appears once the first is answered.

### Contain (25, clamped at 0)
Required: isolate NG-BLD-02 (keep it on, capture image) 4 · kill the process **and** remove persistence 4 · revoke lumen-bot token + rotate staging deploy key 5 · close/block PR #482 and review lumen-bot's other PRs 4 · pull Lumen-7 "turbo" (stop runner, quarantine weights) 4 · block `203.0.113.77` / `lumen-sync.example` at egress + DNS 4.
Neutral (0): report the poisoned fine-tune to the model hub / Lumen maintainers.
Penalties — overreaction: wipe all 38 dev laptops −3 · permanently ban all AI coding tools −2 · shut down git + CI/CD for a week −3. Harmful: reimage NG-BLD-02 before evidence capture −2 · ask Lumen-7 whether it's backdoored (new shell session) −2 · probe `203.0.113.77` from the SOC −5 (ROE violation). Underreaction: delete the password line, merge PR #482, keep the agent running −3.

### Sample lead-ready report (100/100)

> **IOCs:** 203.0.113[.]77 · lumen-sync[.]example · /home/svc-lumen/.cache/.kw/kworker · dbus-index.service · models.hubmirror[.]example/u/lntrn/lumen-7-coder-turbo · PR #482
> **Actions:** Isolated NG-BLD-02 after a triage image; killed PID 2290 and removed dbus-index.service + linger; revoked the lumen-bot token and rotated the staging deploy key; closed and locked PR #482; stopped the agent and quarantined the model weights; blocked 203.0.113.77 and lumen-sync at egress and DNS.
> **Lessons learned:** Sandboxed, ephemeral agent runners; least-privilege, short-lived tokens; mandatory human review of AI-authored PRs; verify model provenance (official source, checksums, signatures); egress allow-list for build hosts; secret scanning in CI.

## Discussion prompts (workshops)

- Where should an AI coding agent run, and what should it be able to reach? (Ephemeral sandbox, no standing credentials, egress allow-list, PR-only write access.)
- Who approves a new model the way you'd approve a new dependency? What does "provenance" mean for model weights?
- Would your code review have caught `|| "fallback"` and `rejectUnauthorized: false` in a PR that claimed "no security-relevant changes"?
- Why is "ban all AI tools" a weaker answer than "pause this model and fix the controls"?
